# Guardrails

coeos-code enforces your safety rules **even when the model goes off the rails** —
they live in the binary, not in a prompt that can be dropped or overridden.

## Controlled shell commands

The `permission.bash` guardrail intercepts every shell command before it runs:

| Command | Behaviour |
|---|---|
| `rm -rf /…` | **Denied** — never executed |
| `rm -rf ~…` | **Denied** |
| `rm -rf …` (anything else) | **Ask** for confirmation |
| `git push --force` / `-f` | **Ask** for confirmation |
| `git reset --hard` | **Ask** for confirmation |
| `git clean -fd` | **Ask** for confirmation |
| `launchctl bootout` | **Ask** for confirmation |
| everything else | Allowed |

On an **ask**, coeos-code stops and shows you the exact command it wants to run —
you approve or decline. On a **deny**, the command is refused outright; there is
no override path from inside a session.

## Method rules (always injected)

Every session boots with the coeos-code method rules active:

1. **Evidence first** — a probability is not a certainty; verify before acting,
   otherwise say "unverified assumption".
2. **No workarounds** — fix the root cause, don't mask the symptom.
3. **Dead horse** — patch stacked on patch means the approach is dead; switch,
   don't keep patching.
4. **Rethink at every step** — no autopilot; re-examine the alternatives at each
   milestone.
5. **Fibonacci story points**, never hours.
6. No emojis in code or commits. coeos-code replies in the user's own language.

The rules live in `~/.codeos/RULES.md` (regenerated by the app on launch) and are
loaded through the instructions mechanism, so they apply to every session without
you having to paste them in.

## Locked provider

coeos-code talks only to the **OdyssAI** provider — the sole entry in the model
picker — exposing two models: **CoeOS** and **CoeOS box**. No other model and no
external endpoint is selectable, by design.

**No hardcoded endpoint.** coeos-code resolves the engine at startup through a fixed
chain, stopping at the first that answers:

1. `CODEOS_ENGINE_URL` environment variable.
2. `~/.codeos/pairing.json` — per-machine provisioned keys
   (`{enrollSecret, engines:[{baseUrl, apiKey}]}`), handled like an SSH key:
   nothing extractable is shipped in the app.
3. The last resolved engine, persisted between runs.
4. LAN discovery — a `/.well-known` probe for `vendor=odyssai.eu` on ports
   `8000` and `4600`, then `POST /admin/pair` using the pre-shared enrollment
   secret.
5. Graceful degradation if none of the above resolve.

The two engines behind those models:

- **OdyssAI-X** — `<engine-host>:8000`, public `/v1`.
- **CoeOS box** — `<box-host>:4600`, the `coeos-box` Docker container, serving `/v1`
  (optionally gated by a static `COEOS_API_KEY`).

**Signed and notarised.** Since v0.2.0 the app is signed with an Apple Developer
ID and notarised by Apple — it installs and runs without `xattr` juggling or
Gatekeeper prompts. The current build is coeos-code 0.3.x (the footer reads
"coeos-code `<version>`").

## Persistent project memory

coeos-code keeps a per-project `.codeos/MEMORY.md` and auto-writes session docs under
`docs/sessions/` (via the `session-doc` plugin) — so decisions and context survive
across sessions instead of living only in a transcript that scrolls away.
