# Memory and automatic docs

coeos-code writes two things **on its own**, without you asking, at the end of a
meaningful session (kicks in around ~6 messages, regenerated every ~4 new ones).

## The session doc

File: `<project>/docs/sessions/SESSION-<date>-<id>.md`

Content: OdyssAI format — **Done / Difficulties / To-do** in Fibonacci points,
plus frontmatter (session id, title, message count). It's the record of what was
done, still readable 3 months later. The `session-doc` plugin drives it.

## The project memory — the differentiator

File: `<project>/.codeos/MEMORY.md`

At each session, coeos-code **extracts the durable lessons** from the work and merges
them into this file (80 lines max): gotchas, verified commands, repo conventions,
environment traps, architecture decisions. It keeps what is still true, corrects
what went stale, and dedupes.

**And crucially**: this file is **reloaded automatically at the start of every
session** on that project. In practice, coeos-code remembers across runs: "on this
repo the build is `bun run build`, the test port is always 14xxx, that schema
ignores inline text." You never re-explain the same trap twice.

## Good to know

- Best-effort: if the engine is unavailable, the session isn't blocked — the doc
  just skips this round.
- Generated by **CoeOS directly** (the model behind coeos-code), not by the session
  itself: no loop, no conversation turn consumed.
- Subagent sub-sessions do **not** generate a doc — only the root session counts.
- These files live inside the repo, so they show up in `git status`. That's
  intended (traceability); add them to the project `.gitignore` if you don't want
  them versioned.
